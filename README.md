# Primitive DB

Учебное консольное приложение, имитирующее работу с базой данных.
Реализованы создание, просмотр списка и удаление таблиц с хранением структуры в JSON.
Управление зависимостями, виртуальным окружением и сборкой выполняется через uv.

## Требования

- Python 3.12 или новее; `.python-version` выбирает Python 3.12 для разработки.
- [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Make для запуска команд из `Makefile`.

## Установка и запуск

Из корня проекта выполните:

```bash
make install
make database
```

Эквивалентные команды без Make:

```bash
uv sync
uv run database
```

`uv sync` создаёт `.venv` в корне проекта и устанавливает пакет и зависимости,
включая Ruff из группы `dev`. Версии зависимостей зафиксированы в `uv.lock`.
Файл `uv.lock` нужно хранить в Git, а `.venv` и `dist` исключены через `.gitignore`.

Запуск модуля напрямую:

```bash
uv run python -m project_2_zadorozhnii_m26_555.primitive_db.main
```

После запуска приложение выводит справку «База данных» и приглашение ко вводу.
Команда `help` повторяет справку, `exit` завершает работу.
Также выйти можно через Ctrl+C или Ctrl+D.

При использовании `uv run` активировать окружение вручную не требуется.
Чтобы запускать `database` без префикса `uv run` на macOS/Linux:

```bash
source .venv/bin/activate
database
```

Команда `project` сохранена как альтернативное имя запуска приложения.

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя_таблицы> <столбец1:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя_таблицы>` | Удалить таблицу |
| `help` | Показать справку |
| `exit` | Завершить работу |

Поддерживаются типы `int`, `str`, `bool`. Имена таблиц и столбцов должны начинаться
с буквы или подчёркивания и содержать только буквы, цифры и подчёркивания.
Имена чувствительны к регистру. Повторяющиеся столбцы запрещены.

При создании укажите хотя бы один столбец. Столбец `ID:int` автоматически добавляется
в начало схемы. Если указать `ID:int` самостоятельно, он будет добавлен только один
раз; другой тип для `ID` запрещён. На этом этапе сохраняется структура таблиц,
работа со строками данных ещё не реализована.

Пример сеанса:

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table users
Таблица "users" успешно удалена.
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
>>>Введите команду: exit
```

Метаданные сохраняются в `db_meta.json` в текущей рабочей папке после успешного
создания или удаления таблицы. При повторном запуске из той же папки таблицы
сохраняются. Перед выполнением каждой команды управления таблицами файл читается
заново. Пример формата:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

Ошибки ввода не завершают приложение. При повреждении JSON или некорректной
структуре метаданных выводится ошибка, исходный файл не перезаписывается.
Для исправления откройте `db_meta.json` вручную; `help` и `exit` остаются доступны.

## Команды разработки

| Команда | Действие |
| --- | --- |
| `make install` | Установка проекта и зависимостей через `uv sync` |
| `make project` | Запуск приложения через `uv run project` |
| `make database` | Запуск базы данных через `uv run database` |
| `make lint` | Проверка кода через `uv run ruff check .` |
| `make build` | Сборка wheel и sdist в `dist/` через `uv build` |
| `make publish` | Сборка и пробная публикация через uv без загрузки в PyPI |
| `make package-install` | Сборка и установка wheel в существующее окружение `.venv` |

`make publish` выполняет `uv publish --dry-run --trusted-publishing never`.
Пакет не загружается в PyPI, поиск токена CI отключён для локальной проверки.
Перед `make package-install` выполните `make install`, чтобы создать окружение.
После установки wheel запустите `.venv/bin/database`, чтобы проверить установленный
пакет без повторной синхронизации исходников через `uv run`.

Добавление обычной зависимости и зависимости для разработки:

```bash
uv add prompt
uv add --dev ruff
```

Форматирование кода:

```bash
uv run ruff format .
```

## Структура

```text
src/
└── project_2_zadorozhnii_m26_555/
    ├── __init__.py
    └── primitive_db/
        ├── __init__.py
        ├── core.py
        ├── engine.py
        ├── main.py
        └── utils.py
```

`main.py` содержит точку входа, `engine.py` — цикл команд и разбор через `shlex`,
`core.py` — проверку схемы и управление таблицами, `utils.py` — чтение и запись JSON.
Настройки пакета, команд `database` и `project` и Ruff находятся в `pyproject.toml`.
Пакет собирается с помощью `uv_build`; секции `[tool.poetry]` не используются.
