# Primitive DB

Учебное консольное приложение, имитирующее работу с базой данных.
Реализованы управление таблицами и CRUD-операции с хранением структуры и данных в JSON.
Управление зависимостями, виртуальным окружением и сборкой выполняется через uv.

## Требования

- Python 3.12 или новее; `.python-version` выбирает Python 3.12 для разработки.
- [uv](https://docs.astral.sh/uv/getting-started/installation/).
- Make — необязательно, только для сокращённых команд из `Makefile`.

## Установка и запуск

Основной способ работы — напрямую через uv, без Make. Из корня проекта выполните:

```bash
uv sync
uv run database
```

При желании можно использовать эквивалентные сокращения через Make:

```bash
make install
make database
```

Команда `make run` также запускает базу данных через `uv run database`.

`uv sync` создаёт `.venv` в корне проекта и устанавливает пакет и зависимости,
включая Ruff из группы `dev`. Версии зависимостей зафиксированы в `uv.lock`.
Файл `uv.lock` нужно хранить в Git, а `.venv` и `dist` исключены через `.gitignore`.

Запуск модуля напрямую:

```bash
uv run python -m project_2_zadorozhnii_m26_555.primitive_db.main
```

После запуска приложение выводит справку «База данных» и приглашение ко вводу.
Команда `help` повторяет справку, `exit` завершает работу.
Также выйти можно через Ctrl+C или Ctrl+D.

При использовании `uv run` активировать окружение вручную не требуется.
Чтобы запускать `database` без префикса `uv run` на macOS/Linux:

```bash
source .venv/bin/activate
database
```

Команда `project` сохранена как альтернативное имя запуска приложения.

```bash
uv run project
```

## Управление таблицами

| Команда | Действие |
| --- | --- |
| `create_table <имя_таблицы> <столбец1:тип> ...` | Создать таблицу |
| `list_tables` | Показать список таблиц |
| `drop_table <имя_таблицы>` | Удалить таблицу |
| `help` | Показать справку |
| `exit` | Завершить работу |

Поддерживаются типы `int`, `str`, `bool`. Имена таблиц и столбцов должны начинаться
с буквы или подчёркивания и содержать только буквы, цифры и подчёркивания.
Имена чувствительны к регистру. Повторяющиеся столбцы запрещены.

При создании укажите хотя бы один столбец. Столбец `ID:int` автоматически добавляется
в начало схемы. Если указать `ID:int` самостоятельно, он будет добавлен только один
раз; другой тип для `ID` запрещён. При удалении таблицы удаляется и её файл данных.

Пример сеанса:

```text
>>>Введите команду: create_table users name:str age:int is_active:bool
Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool
>>>Введите команду: create_table users name:str
Ошибка: Таблица "users" уже существует.
>>>Введите команду: list_tables
- users
>>>Введите команду: drop_table users
Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
Таблица "users" успешно удалена.
>>>Введите команду: drop_table products
Ошибка: Таблица "products" не существует.
>>>Введите команду: exit
```

Метаданные сохраняются в `db_meta.json` в текущей рабочей папке после успешного
создания или удаления таблицы. При повторном запуске из той же папки таблицы
сохраняются. Перед выполнением каждой команды управления таблицами файл читается
заново. Пример формата:

```json
{
  "users": ["ID:int", "name:str", "age:int", "is_active:bool"]
}
```

Ошибки ввода не завершают приложение. При повреждении JSON или некорректной
структуре метаданных выводится ошибка, исходный файл не перезаписывается.
Для исправления откройте `db_meta.json` вручную; `help` и `exit` остаются доступны.

## CRUD-операции

| Команда | Действие |
| --- | --- |
| `insert into <таблица> values (<значение1>, ...)` | Добавить запись |
| `select from <таблица>` | Показать все записи через PrettyTable |
| `select from <таблица> where <столбец> = <значение>` | Выбрать записи по условию |
| `update <таблица> set <столбец> = <значение> where <столбец> = <значение>` | Обновить записи |
| `delete from <таблица> where <столбец> = <значение>` | Удалить записи по условию |
| `info <таблица>` | Показать структуру и количество записей |

Все поля обязательны. В `insert` передаются значения в порядке столбцов, **без ID**.
ID вычисляется как максимальный существующий ID плюс один, для пустой таблицы — 1.
Изменять ID через `update` нельзя.

Строки должны быть в одинарных или двойных кавычках, числа — без кавычек,
логические значения — `true` или `false`. Преобразования между типами нет:
`"28"` — строка, `28` — целое число, `true` — логическое значение.
В строках разрешены пробелы, запятые и знаки равенства; кавычки можно экранировать
обратной косой чертой. Поддерживаются JSON-экранирования (`\\`, `\"`, `\n`, `\t`,
`\uXXXX`) и `\'` для апострофа. Регистр команд и имён столбцов учитывается.

`where` поддерживает одно условие равенства. Для `update` и `delete` оно обязательно.
В `set` можно указать несколько присваиваний через запятую. Обновление и удаление
применяются ко всем подходящим записям. Неизвестные столбцы и неверные типы
отклоняются, в том числе для пустой таблицы.

Пример:

```text
create_table users name:str age:int is_active:bool
insert into users values ("Sergei", 28, true)
select from users
select from users where age = 28
update users set age = 29 where name = "Sergei"
select from users where ID = 1
delete from users where ID = 1
y
info users
exit
```

Данные хранятся в `data/<имя_таблицы>.json` относительно текущей рабочей папки.
Директория создаётся автоматически и исключена из Git. Каждая запись — словарь:

```json
[
  {"ID": 1, "name": "Sergei", "age": 28, "is_active": true}
]
```

При отсутствии файла таблица считается пустой. Повреждённые JSON-файлы,
несоответствие данных схеме и повторяющиеся ID вызывают ошибку без перезаписи
исходного файла. Изменения сначала записываются во временный файл, затем заменяют
файл таблицы. После перезапуска данные доступны из той же рабочей папки.

## Декораторы и кэширование

Общая логика вынесена в `src/project_2_zadorozhnii_m26_555/decorators.py`.
Все декораторы сохраняют имя, документацию и доступ к исходной функции
через атрибут `__wrapped__`. Эти атрибуты копируются вспомогательной функцией
без дополнительных стандартных модулей.

- `handle_db_errors` обрабатывает отсутствие файла, таблицы или столбца,
  ошибки валидации, файловые ошибки и непредвиденные исключения.
  Сообщение выводится один раз, консоль продолжает принимать команды.
  Функция `command_error()` создаёт обычный `ValueError` с готовым сообщением:
  оно выводится без дополнительного префикса, как в примерах задания.
  Во вложенных вызовах исключение передаётся наружу до общей границы обработки,
  чтобы операция не продолжалась с некорректными данными.
  Глубина вложенных вызовов хранится в замыкании; приложение однопоточное.
- `confirm_action(action_name)` запрашивает подтверждение перед `drop_table`
  и `delete`. Только ответ `y` после удаления пробелов разрешает действие.
  Любой другой ответ, пустая строка, Ctrl+C или Ctrl+D отменяют операцию;
  данные не изменяются и сообщение об успешном удалении не выводится.
- `log_time` выводит время выполнения `insert` и `select`, измеренное через
  `time.monotonic()`: `Функция select выполнилась за 0.001 секунд.`
  Время выводится и при ошибке операции. Ожидание ответа на подтверждение
  удаления не входит в замеры этих функций. При попадании в кэш `select`
  повторно не вызывается, поэтому нового замера нет.
- `create_cacher()` возвращает функцию `cache_result(key, value_func)`.
  Словарь кэша хранится в замыкании; для сохранённого ключа вычисление повторно
  не вызывается. Метод `cache_clear()` очищает это замыкание.

В `engine.py` ключ кэша `select` включает имя таблицы, условие `where`
(или `null` при его отсутствии) и текущее содержимое данных. Условие и данные
приводятся к стабильному JSON с отсортированными ключами. Порядок ключей условия
не влияет на попадание в кэш, а числа и логические значения различаются.
Изменение данных, в том числе внешнее изменение JSON, не возвращает устаревший
результат. Создание и удаление таблиц, вставка, обновление и удаление записей
очищают кэш после успешного сохранения изменений. Ошибка или отмена удаления
не очищает кэш. Само ядро не управляет кэшем: его жизненный цикл связан с командами
и сохранением файлов в `engine.py`.
Возвращаемые записи копируются, поэтому вызывающий код не может испортить кэш.
Кэш живёт только в текущем процессе; чтение и проверка JSON при этом сохраняются.

При прямом вызове функций ядра ошибка или отмена возвращает `None`.
Пустой результат выборки или удаления — обычный список `[]`, а удаление
последней таблицы — словарь `{}`; эти результаты не считаются ошибками.

Пример отмены и подтверждения:

```text
>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: n
Операция отменена.
>>>Введите команду: delete from users where ID = 1
Вы уверены, что хотите выполнить "удаление записей"? [y/n]: y
Запись с ID=1 успешно удалена из таблицы "users".
```

Перед запросом подтверждения удаления записей может выводиться время `select`,
поскольку приложение предварительно находит подходящие строки.

## Команды разработки

Все команды выполняются из корня проекта. Makefile только сокращает вызовы uv;
он не обязателен для установки, запуска, проверки или сборки.

| Действие | Напрямую через uv | Через Make (необязательно) |
| --- | --- | --- |
| Установить проект и зависимости | `uv sync` | `make install` |
| Запустить базу данных | `uv run database` | `make database` или `make run` |
| Запустить через альтернативное имя | `uv run project` | `make project` |
| Проверить код линтером | `uv run ruff check .` | `make lint` |
| Проверить форматирование | `uv run ruff format --check .` | — |
| Отформатировать код | `uv run ruff format .` | — |
| Собрать wheel и sdist в `dist/` | `uv build` | `make build` |
| Собрать и проверить публикацию | `uv build && uv publish --dry-run --trusted-publishing never` | `make publish` |
| Собрать и установить wheel в `.venv` | `uv build && uv pip install --python .venv/bin/python dist/*.whl` | `make package-install` |

Пробная публикация выполняется командой `uv publish --dry-run --trusted-publishing never`.
Пакет не загружается в PyPI, поиск токена CI отключён для локальной проверки.
Перед ней нужна сборка `uv build`; `make publish` запускает сборку автоматически.
Перед установкой wheel выполните `uv sync` (или `make install`), чтобы создать
окружение `.venv`. Параметр `--python .venv/bin/python` направляет установку
в это окружение, а не в системный Python.
После установки wheel запустите `.venv/bin/database`, чтобы проверить установленный
пакет без повторной синхронизации исходников через `uv run`.

Добавление обычной зависимости и зависимости для разработки:

```bash
uv add prompt
uv add prettytable
uv add --dev ruff
```

Форматирование кода:

```bash
uv run ruff format .
```

## Проверка перед сдачей

Полная последовательность напрямую через uv, без Make:

```bash
uv sync
uv run ruff check .
uv run ruff format --check .
uv build
uv publish --dry-run --trusted-publishing never
uv pip install --python .venv/bin/python dist/*.whl
```

Эквивалентная последовательность с сокращениями из Makefile:

```bash
make install
make lint
uv run ruff format --check .
make publish
make package-install
```

После установки wheel запустите `.venv/bin/database` и пройдите полный сценарий
из финальной демонстрации: создание таблицы, вставка, выборка, обновление, удаление
записей и таблицы. Ответ `y` подтверждает удаление, `n` отменяет его.
Проверьте также неправильный тип значения, неизвестную команду и повторное
создание таблицы. Для возврата к editable-установке выполните `uv sync --locked`.

Тесты преподавателя не входят в репозиторий. Их результат нужно проверять
отдельно в системе курса; локальная проверка Ruff и сборки их не заменяет.

## Структура

```text
src/
└── project_2_zadorozhnii_m26_555/
    ├── __init__.py
    ├── constants.py
    ├── decorators.py
    ├── errors.py
    └── primitive_db/
        ├── __init__.py
        ├── core.py
        ├── engine.py
        ├── main.py
        ├── parser.py
        └── utils.py
```

`main.py` содержит точку входа, `engine.py` — цикл команд и вывод PrettyTable,
`parser.py` — разбор команд, значений и условий, `core.py` — управление таблицами
и CRUD, `utils.py` — проверку структуры столбцов, чтение, запись и удаление JSON.
`delete_table_data()` вызывается из `engine.py` после удаления таблицы из
метаданных; отсутствие файла не считается ошибкой.
`decorators.py` содержит декораторы обработки ошибок, подтверждения, времени
и фабрику замыкания для кэширования. `errors.py` содержит функцию создания
стандартного исключения с готовым сообщением, без собственного класса.
В `constants.py` вынесены пути файлов, поддерживаемые типы и настройки парсера.
Все функции снабжены короткими docstring. Код процедурный, без собственных классов;
из стандартной библиотеки используются только `json`, `shlex`, `time` и `os`,
из внешних библиотек приложения — `prettytable` и `prompt`.
Настройки пакета, команд `database` и `project` и Ruff находятся в `pyproject.toml`.
Пакет собирается с помощью `uv_build`; секции `[tool.poetry]` не используются.
